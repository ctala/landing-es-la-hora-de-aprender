Sequoia: La próxima empresa de $1T no vende software
~15 minutos
DEBATE
C

El 5 de marzo, Julien Bek, socio de Sequoia Capital, publicó un artículo que se está citando en todos lados. La tesis central:

"La próxima empresa de 1 trillion de dólares va a ser una empresa de software disfrazada de firma de servicios."
— Julien Bek, Sequoia Capital · sequoiacap.com/article/services-the-new-software · 5 Mar 2026
C

No van a vender el software. Van a vender el trabajo que el software hace. Él lo llama Copilot vs Autopilot:


  • Copilot → te vende la herramienta. Tú la usas, tú te responsabilizas del resultado.
  • Autopilot → te vende el resultado. Le dices qué necesitas, ellos lo entregan.

Ejemplo concreto: Una empresa gasta $10.000/año en QuickBooks y $120.000 en el contador. La próxima empresa grande no te vende software contable mejor. Te dice: "nosotros cerramos tus libros" — con IA, más barato, más rápido.

API-First: si los agentes no pueden usar tu plataforma, no existes
~15 minutos
PRÁCTICO

Aaron Levie, CEO de Box, publicó un ensayo esta semana con una frase que sintetiza todo:

"Si no tienes API para una feature, es como si esa feature no existiera para los agentes."
— Aaron Levie, CEO de Box · Mar 2026
C

Y acá me toca ser honesto: esto no es nuevo para mí. En Pago Fácil, hace 8 o 9 años, tomamos la decisión de ser API-first desde el día uno. No porque anticipara los agentes — sino porque era buena ingeniería. Cada funcionalidad tenía que poder consumirse por API antes de que existiera la UI.


¿El resultado hoy? Cualquier agente se puede integrar sin fricción. Una decisión de 2016 resulta ser la jugada correcta para 2026.

🎤 Pregunta para Diego

"¿Cuántas startups que ves están pensando en API-first desde el día cero, o siguen construyendo la UI primero y la API como afterthought?"

✅ ¿Qué significa ser "amigable con los agentes"? — Checklist práctico

No es solo tener una API. Es que esa API permita que un agente haga el trabajo completo, sin necesitar un humano en el medio.

  • ✅
    Signup por API — Jared Friedman (YCombinator): "La mayoría de las mejores herramientas de developers todavía no dejan crear una cuenta vía API. En la era de Claude Code, eso es un error fatal." Si un agente no puede registrarse solo, no existe para él.
  • ✅
    Webhooks y eventos — El agente necesita saber cuándo algo cambió. Sin webhooks, tiene que preguntar cada 5 minutos. Ineficiente y caro.
  • ✅
    Documentación estructurada (OpenAPI spec) — Los agentes consumen tu documentación para entender cómo usar tu API. Si está mal organizada, alucina. Ejemplos reales + errores bien documentados son obligatorios.
  • ✅
    Rate limits razonables + pricing por consumo — Un agente puede hacer 10.000 llamadas donde un humano haría 10. Si solo tienes seats, estás bloqueando la adopción y dejando plata sobre la mesa.
  • ✅
    MCP Server (Model Context Protocol) — El estándar de Anthropic que ya adoptaron la mayoría de herramientas de agentes. Si tienes un MCP server, cualquier coding agent se integra en minutos con tu plataforma.

Todo lo que hablamos hoy puede sonar muy "big tech". Quiero cerrar con algo que cualquiera puede usar esta semana.


Alguien publicó en Reddit un repositorio llamado Agency Agents — en 12 horas tenía 50 requests. La idea: 80 agentes especializados, con personalidad, procesos y entregables concretos, que se instalan en Claude Code con un comando.

# Instalar en Claude Code (una línea) cp -r agency-agents/* ~/.claude/agents/ # Con instalador interactivo (detecta tus herramientas) ./scripts/install.sh
C

Abres Claude Code y le dices: "Usa el Backend Architect para diseñar esta API" o "Activa el Security Engineer y revisa este código". Tienes Frontend Developer, Growth Hacker, UX Researcher, Legal Compliance — todos disponibles, todos gratis.


Funciona también en Cursor, Gemini CLI, Windsurf y Aider. Repo: github.com/msitarzewski/agency-agents
